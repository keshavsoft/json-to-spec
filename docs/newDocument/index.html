Three ways to create the same UI

01 · ORIGINAL HTML

Write the DOM as HTML

The browser's HTML parser creates the elements. 
<div id="test-content">
  <label>Name</label>
  <p>Test Content</p>
</div>

02 · VANILLA JAVASCRIPT

Create the DOM with JS

Native DOM APIs create and connect every node. 
const div = document.createElement("div");
div.id = "test-content";

const label = document.createElement("label");
label.textContent = "Name";

const text = document.createElement("p");
text.textContent = "Test Content";

div.append(label, text);

document.querySelector("#app")
  .append(div);

03 · JSON-TO-SPEC

Describe the DOM as JSON

The compiler converts structure + data into a concrete spec. 
const structure = {
  tagName: "div",
  attributes: { id: "test-content" },
  children: [
    { tagName: "label",
      textContent: "${name}" },
    { tagName: "p",
      textContent: "${message}" }
  ]
};

const data = {
  name: "Name",
  message: "Test Content"
};

const spec = compile({
  inStructure: structure,
  inData: data
});
Compiled specification → DOM

Test Content

The important difference: Original HTML directly describes the DOM. Vanilla JavaScript creates DOM nodes imperatively. json-to-spec separates the UI structure from its data, compiles both into a concrete JSON specification, and leaves that specification ready for a downstream DOM rendering layer.

What json-to-spec adds

1 · Structure

Define the UI tree once: tags, attributes, text placeholders and operations.

2 · Data

Supply values separately. The same structure can be compiled against different data.

3 · Compile

Resolve values, replace ${...} tokens and expand iteration nodes into concrete specification JSON.
